# Privacy and Data Protection Readiness

## Current data posture

The public project is configured and documented for synthetic demonstration data. Production use with identifiable health data is not authorized by the project itself.

## Before processing health data

The deploying organization must:

1. identify the controller, processor, and authorized users
2. document purpose, lawful basis, and data categories
3. complete a Data Protection Impact Assessment where required
4. apply data minimization and pseudonymization
5. define consent and withdrawal handling
6. set retention and secure deletion periods
7. document data-subject request procedures
8. review cross-border transfers and vendors
9. test breach detection, escalation, and notification
10. execute appropriate contractual and organizational controls

## Technical controls still required for production

- enforced role-based access beyond owner isolation
- server-enforced export approval
- configurable retention and deletion workflows
- tested backup and disaster recovery
- centralized security monitoring and alerting
- independent penetration testing
- documented encryption and key-management responsibilities
- formal incident-response ownership

## Prohibited content

Do not place names, addresses, telephone numbers, government identifiers, medical record numbers, or other directly identifying patient data in the demonstration deployment.
